# Official benchmark scoring protocol

Effective 2026-10-04, performance acceptance uses each suite's upstream
measurement and scoring procedure. The earlier paired wall-clock aggregation
is diagnostic evidence only. Static jumps, layout objectives and simulated
hardware events explain optimization behavior; they are not benchmark scores.

## Embench 1.0

Use the pinned commit `0466a18e4f6b47e19598d7c6ba72916d54b68f65`, all 19
programs, and unchanged `build_all.py`, `benchmark_speed.py`,
`benchmark_size.py`, `pylib/run_native.py`, and `pylib/embench_core.py`.
The official [manual](../benchmarks/embench/doc/README.md) documents
`--baseline-output` and `--baselinedir` for a local reference platform.

The speed reference is **original CompCert on this same host**, generated by
the official script. Candidate and repeated baseline scores are computed by
that script against the saved reference. This is an official-harness score
with a declared local reference, not a score normalized to the published
Cortex-M4 platform. Both builds use `CPU_MHZ=10000` as the common workload
scale, `WARMUP_HEAT=1`, `-O -fall`, and the same native support/libm. The scale
was chosen before these runs to extend the existing millisecond workloads.
It does not describe the host clock; no score/MHz is claimed.

Use CPU 40, serial execution, and the upstream native target's `time -p`
whole-process wall-clock measurement. Do not replace its timer/parser or
rescale its output. Its 10 ms resolution limits small-effect inference,
especially for the fastest programs. Save one baseline reference, then four
complete official score runs in order baseline, C1, C1, baseline. Report every
score without a custom composite or selection of the best run. Upstream
geometric SD is dispersion across programs, not a temporal confidence interval.
The native parser does not reject nonzero RET values; separately require all
38 unchanged benchmark verifiers to exit zero before scoring.

Build size separately with `-Os -fall`, official dummy crt0/libc/libgcc/libm,
and no system startup/default libraries. Use the official default `.text`
metric. Retain both same-host-baseline-relative scores and scores relative
to the unchanged published `baseline-data/size.json`. CompCert does not
support GCC's function/data-section flags; omit them uniformly and record
the full flags. Size-only dummy-library executables are not run.

The added native CompCert chip configurations reuse the upstream empty chip
support files, with settings supplied through documented command-line options.
The size configuration supplies two extra dummy symbols (`fabs`, `fabsf`):
CompCert emits calls where GCC uses builtins, and the upstream dummy libm omits
these functions. These zero-return stubs are linked only into size binaries.
No official benchmark, harness, baseline-data or scoring code is
edited. Preserve source/compiler/binary hashes, full command lines, compiler
logs, raw reference JSON and every official result.

Reproduce from `compcert/` in a fresh results directory:

```sh
source env.sh
python3 -m pip install --target env/embench-python pyelftools==0.32
python3 performance/official-embench.py build
python3 performance/official-embench.py run
```

## Other suites

MiBench provides per-program `COMPILE`, `runme_small.sh` and `runme_large.sh`
instructions and inputs; no standardized aggregate score has been identified
in the pinned distribution or [official instructions](https://vhosts.eecs.umich.edu/mibench/source.html).
Do not label an average over the CompCert-compatible subset an official
MiBench score. Report upstream per-program outputs/measurements and coverage;
unsupported or baseline-invalid programs remain visible.

PolyBench results must use its supplied timing harness, documented dataset
and reporting procedure. A private aggregate over kernels is not an official
PolyBench score. CompCert regression tests remain correctness checks.

C3 profile collection may collect edge counts for optimization, but its
performance acceptance must follow this protocol. Never substitute its
internal objective improvement for an official benchmark score improvement.
