# rust-base64 `7509b25`: allocate bytes before encoding

The exact historical change replaces `String::with_capacity` plus `encode_config_buf` with a zeroed byte vector, `encode_config_slice`, and `String::from_utf8` in public `encode_config`. [`reproduce.py`](reproduce.py) checks the archived parent/child `src/encode.rs` Git blob IDs, builds both complete historical crates with Rust 1.99 and cached semver-compatible `byteorder` 1.5.0, then runs the same [public-API probe](probe.rs) against each. `--cap-lints allow` is needed because this older crate denies warnings emitted by the newer compiler; the historical source is otherwise unchanged.

The [result](result.json) compares returned text, length, and `String::capacity()` for every input length 0–512, two byte patterns, and all 12 public `Config::new` combinations (three character sets, padding on/off, whitespace stripping on/off): **12,312 cases in debug and 12,312 in release, with zero differences**. Whitespace stripping is a decode setting but is included for completeness. This is bounded native testing, not an equivalence proof. The previous whole-function Aeneas attempt still lacks the required `String`/`Vec` model and fails before a relational theorem. The selected verdict remains `UNSUPPORTED` for that checker; no official before/after benchmark score was measured for this historical commit.
