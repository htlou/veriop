# SymCRust historical checks

The source pin is `c2e575ace0ea4b6b7a4184c1f19b81d1d5b2b5be`. The three checked performance commits and their Charon/Aeneas logs are indexed by [`../../results/SymCrypt-partial.json`](../../results/SymCrypt-partial.json). Each `old.llbc`/`new.llbc` was extracted from `git archive <commit>^`/`git archive <commit>` restricted to `SymCRust/`, using `benchmarks/tools/symcrust-aeneas/charon/bin/charon cargo --preset=aeneas --start-from <unit> --dest-file <file> -- --lib` with `RUSTUP_TOOLCHAIN=nightly-2026-06-01`. Translation used the matching bundled `aeneas` with `-backend lean -loops-to-rec -sequential`. Both sides compiled and extracted for every listed unit. In the isolated archives only, the private Microsoft Cargo registry override was removed; the original target-feature rustflags were retained, and public crates.io supplied the lockfile dependencies. The pinned repository itself was not modified.

`a28bce2` fails Aeneas on `&raw mut` in the new heap initializer. `b1dadd6` fails on raw-pointer use in the unchanged AES-GCM FFI entry. `1298a64` fails on raw-pointer vector loads/stores in the new NTT intrinsics. These are **UNSUPPORTED**, not evidence of inequality.

The separate `c2e575a/` evidence concerns a newly added *experimental* optimized Keccak implementation. Run `python3 history-eq/rust/SymCrypt/c2e575a/check_bridge.py` from the project root. It matches all 15 pre-commit Aeneas definitions to the renamed post-commit textbook definitions and checks that the generated post-commit definitions equal the published proof model. `axioms.log` records a successful Lean check of the published `keccak_permute_textbook_eq_opt` theorem: only `propext`, `Classical.choice`, and `Quot.sound` are used. The production `keccak_permute` still calls the textbook function at the pinned commit, so this theorem is recorded as a verified **experimental pair**, not a commit-level production optimization result.
