# regex `5e987889`: direct existence search

**Whole-commit verdict: unverified.** The historical commit `5e98788947b28da3da27f4e156b877eb0cb1593e` changes both the byte and Unicode `Regex::is_match_at` wrappers from `self.shortest_match_at(...).is_some()` to the underlying searcher's `is_match_at(...)`. `source.diff` and the four `re_{bytes,unicode}.{old,new}.rs` files are exact historical Git objects, checked by `verify.sh`.

The unchanged historical `shortest_match_at` wrappers delegate to the same searcher's `shortest_match_at`. Therefore the missing semantic obligation is: for the same searcher, text, and start offset, does `searcher.is_match_at(text,start)` equal `searcher.shortest_match_at(text,start).is_some()`? The historical `src/exec.rs` implementation and `Cargo.toml` blobs are missing on both sides of this partial checkout (`source-availability.log`), so the original crate and its real searcher cannot be extracted through Charon here.

The local parent and child trees both identify `src/exec.rs` as Git blob `d5fad1c0ebbe15c535f5d29ffb6cb72ed1ce2ff9`. A [public Rust-toolchain mirror](https://android.1.googlesource.com/toolchain/rustc/+/2f3fdfeb95384b9046ea35b3532e23c652eca660/vendor/regex/src/exec.rs) indexes a vendored file under that exact blob ID. This identifies a possible exact recovery source, but the complete file bytes have not been retrieved and hash-checked locally; `Cargo.toml` is still missing. The checker result is unchanged.

The indexed `exec.rs` text shows matching literal and DFA dispatch decisions: the shortest path maps a literal or DFA match to `Some(end)` and no match to `None`, while the direct path maps them to `true` and `false`. The added [Lean lemmas](Equivalence.lean) prove the Aeneas-extracted wrappers equal for every literal result and every DFA `Match`/`NoMatch` result. A DFA `Quit` delegates to NFA on both sides; the lemma reduces that case to the still-unproved NFA relation. These lemmas are a source-level dispatch model, not an extraction of the unavailable historical `exec.rs`; they do not establish whole-wrapper equivalence for all regexes.

`contract.rs` is a **source-audited output abstraction**, not the historical crate: it accepts the two searcher results independently as `shortest: Option<usize>` and `direct: bool`. Charon extracted that Rust program; Aeneas generated `lean/Contract.lean` without `sorry` or `admit`. The checked theorem in `Equivalence.lean` states that old and new wrapper outputs are equal **if and only if** `shortest.is_some() == direct`; `lean-model.log` and `lean-proof.log` typecheck. The theorem identifies the exact dependency but does not discharge it for the historical searcher. It proves neither full byte nor full Unicode `Regex::is_match_at` equivalence, and supplies no counterexample.
