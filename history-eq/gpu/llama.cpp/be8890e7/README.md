# llama.cpp `be8890e7`: Q6_K repacked generic GEMV

**Scoped verdict: `NOT_EQUIV` for strict FP32 bit equality.** The parent's `ggml_vec_dot_q6_K_q8_K_generic` is called once for each of eight Q6_K rows. The child packs those same rows with `make_block_q6_Kx8` and calls `ggml_gemv_q6_K_8x8_q8_K_generic` once. With one 256-element Q8_K activation block and the first deterministic input from [the reproducer](reproduce.py), row 0 is `0x44362ccd` before and `0x44362ccc` after, a one-ULP difference. [Clang 20, GCC 11, and GCC 11 with AddressSanitizer/UndefinedBehaviorSanitizer](result.json) all produce this witness. The sanitizer run disables leak detection because the sandbox's ptrace environment prevents LeakSanitizer from starting; it reports no address or undefined-behavior error.

The [generated C++ harness](historical.cpp) embeds the exact parent dot function and child packing/GEMV functions from their pinned Git blobs; [source SHA-256 hashes and all commands](result.json) are recorded. The only change to the parent body is two explicit `void *` casts needed to compile its original C syntax in the shared C++ harness. The Q6_K, Q8_K, and Q6_Kx8 structures match the pinned headers and have checked sizes. Each Q6_K scale is FP16 `0x3c00` (exactly `1.0`), so the harness's FP16 converter asserts that bit pattern and returns `1.0`. All quantization bytes are initialized, the Q8_K scale is `0.7f`, and the input generator seed is fixed in the harness.

This is a concrete execution counterexample to **bitwise equality of these two generic functions under the recorded compiler settings**. It does not show an error beyond a numerical tolerance, a whole-model output change, or a difference in the ARM i8mm implementation that production dispatch normally selects. Alive2 did not prove or disprove the full kernel pair. No official historical before/after benchmark score was measured. Reproduce with `python3 -B history-eq/gpu/llama.cpp/be8890e7/reproduce.py` from the project root.
