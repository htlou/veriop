# llama.cpp `dafae66cc242` — Vulkan K-quant subgroup rewrite

**Verdict: `UNSUPPORTED` for whole-kernel equivalence with the installed checkers.** The [source-locked check](reproduce.py) covers the four historical Q2_K, Q3_K, Q4_K, and Q5_K vector-multiply shaders and their shared base and host files. The old base defines `K_QUANTS_PER_ITERATION = 2`, and each old shader launches 32 invocations but computes `tid = gl_LocalInvocationID.x / 2`. At the first reduction step (`s = 16`), invocations 0 and 1 both execute `tmp[tid] += tmp[tid + s]` with `tid = 0`. They write the same shared-memory location between barriers. [Z3 reports `sat`](old_collision.log) for that concrete conflict.

The new shaders use the unique invocation index as `tid`. For any positive reduction step with `2s` no greater than the workgroup size, Z3 finds [no distinct same-stage writers](new_distinct_writers.log) and [no cross-invocation read/write overlap](new_read_write_overlap.log) in this reduction loop. These checks establish an old write conflict and a new address property. They do **not** establish a numerical output difference, full GPU race semantics, or equality/refinement of the two shaders. In particular, the rewritten lane assignment and floating-point accumulation order were not compared on a Vulkan device. [The result file](result.json) records every exact Git blob ID and query result.

Run `python3 -B history-eq/gpu/llama.cpp/dafae66cc242/reproduce.py` from the project root. Z3 was invoked directly from a Kuiper installation; **Kuiper itself did not verify this historical pair**. No official before/after benchmark score was measured.
