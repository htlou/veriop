# llama.cpp `55c509da`: PowerPC `save_res` refactor

**Scoped verdict: `EQUIV_PARTIAL`.** This commit changes `tinyBLAS_Q0_PPC::save_res` from template parameters `<RM,RN>` to integer arguments, while also refactoring much larger quantized packing paths. The [reproduction script](reproduce.py) extracts both exact historical `save_res` bodies and checks every `RM,RN` pair from 1 through 4 at `ldc=8`, plus four offsets used by the larger 4×4 tile callers. With a valid, aligned 768-byte `Buffers` object, [Alive2 proves both directions for all 20 cases, 40/40 checks](result.json); the individual [forward](forward-compare_4_4_4_4_12.log) and [reverse](backward-compare_4_4_4_4_12.log) logs are retained for every case.

The wrapper replaces PowerPC `vector float` with the same-sized 128-bit Clang vector type and compiles on x86-64 with Clang 20 `-O2`. Before comparison, it removes unsupported alias metadata/attributes symmetrically and adds `nonnull align 16 dereferenceable(768)` to both LLVM arguments to express valid, disjoint matrix and accumulator storage in the harness. Each check also uses Alive2's `--fail-src-ub`. This establishes the output-write relation for `save_res` under those conditions; it does not prove the changed packing functions, MMA arithmetic, PowerPC code generation, or the full matrix multiplication. The source, extracted-snippet, and normalized-IR hashes are in [result.json](result.json).

No official before/after llama.cpp benchmark score for this historical commit was measured here. Reproduce from the project root with `python3 -B history-eq/gpu/llama.cpp/55c509da/reproduce.py`.
