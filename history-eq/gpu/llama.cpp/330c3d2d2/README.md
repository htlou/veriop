# llama.cpp `330c3d2d2`: Vulkan expert-row compaction

**Whole-kernel output verdict: `UNKNOWN`.** The commit replaces one-subgroup expert-row scanning with workgroup-wide ballot compaction in `mul_mm.comp` and `mul_mm_cm2.comp`. [The reproducer](reproduce.py) locks both historical shader pairs by [Git-blob SHA-256](result.json) and checks the relevant loop, ballot, rank, and coordinate expressions against those sources.

Under a **256-invocation workgroup, subgroup size 32, and natural mapping** `LocalInvocationIndex = SubgroupId × 32 + SubgroupInvocationId`, [nine Z3 queries](rank.log) are `unsat`: arbitrary per-invocation expert-hit bits give the same compacted index for each of eight subgroups and the same total selected-row count. Omitting the new subgroup-base term makes the negative control `sat`. [A separate bit-vector query](fastmod.log) proves the new `fastmod(a,b)` equals unsigned `a % b` for all 32-bit `a` and positive `b`; [32 more queries](power2.log) prove the power-of-two quotient shortcut for every 32-bit power-of-two divisor. The non-power-of-two `ii0 = i - (i / nei0) * nei0` uses the standard unsigned quotient/remainder identity, but it was not separately discharged by Z3.

The natural mapping is a real proof precondition. [Vulkan specifies no direct relation between subgroup-local IDs and local invocation IDs or indices](https://docs.vulkan.org/refpages/latest/refpages/source/SubgroupLocalInvocationId.html). A [satisfiable two-lane permutation model](lane-permutation.log) places local index 1 at subgroup lane 0 and local index 0 at lane 1. When both rows match the expert, the old scan's first two `row_ids` are `[0,1]`, while the new scan's are `[1,0]`. This is an **internal order** difference under that model; it does not establish a different final matrix because later shader stages may use each row ID consistently for both load and store. Whether this mapping occurs in the pinned pipeline and whether the output tensors agree remain unverified.

The checks do not execute SPIR-V, model barriers and memory visibility, cover other workgroup/subgroup sizes, or measure an official historical before/after benchmark score. Z3 was invoked directly from the local Kuiper package; Kuiper itself did not check this commit. Reproduce with `python3 -B history-eq/gpu/llama.cpp/330c3d2d2/reproduce.py` from the project root.
