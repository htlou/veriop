# `2cd43f49`: llamafile SGEMM API change

**Scoped verdict: `NOT_EQUIV` for both the direct helper and a complete one-thread `ggml_mul_mat` call on x86-64 with llamafile enabled.** [`reproduce.py`](reproduce.py) verifies and builds the exact historical `sgemm.cpp`, `sgemm.h`, and five required headers on both sides with AVX2/FMA/F16C. It maps the new `ggml_compute_params` fields `ith=0,nth=1` to the old function's thread arguments. The support definitions provide a correct zero entry for the FP16 lookup table and a no-op single-thread barrier.

For `m=4,n=2,k=8`, zero F16 matrix A, one-valued F32 matrix B, and output initialized to −1, the [old function](old-f16_f32.log) returns `true` and writes zero to the output; the [new function](new-f16_f32.log) returns `false` and leaves the output at −1. A shared F32×F32 [old](old-f32_f32_control.log)/[new](new-f32_f32_control.log) control returns `true` and zero on both sides. The [result](result.json) records all exact Git blob IDs, object hashes, and outputs.

The new `false` permits the surrounding ggml caller to use another matrix-multiplication implementation. The [full-caller probe](caller_probe.cpp), reproducible with `python3 history-eq/gpu/llama.cpp/2cd43f49/reproduce_caller.py`, builds the exact old and new historical `ggml/` CPU libraries with `GGML_LLAMAFILE=ON`. Two controls agree: the original zero F16×F32 case yields eight zeros, and F16 rows containing 1 through 8 with all-one F32 input yield eight 36s ([old](old-caller.log), [new](new-caller.log)).

The third valid input exposes a **final-tensor difference**. With a 4×8 F16 matrix of ones and an 8×2 F32 matrix of `1.0001f`, the old caller returns eight `0x1.00068ep+3` values (8.000800132751465), while the new caller returns eight `0x1p+3` values (8.0). The old helper handles F16×F32 directly; the new helper declines, and the caller converts the right operand to F16 for its fallback path. With llamafile disabled, both historical callers return eight 8.0s ([old control](old-caller-no-llamafile.log), [new control](new-caller-no-llamafile.log)). This is a concrete native counterexample to **exact-output equivalence** of the final `ggml_mul_mat` tensor under the stated build and input; it does not assess an approximate numerical tolerance or all shapes and configurations. Alive2 was not used for the full C++ template and threadpool function, and no official historical before/after benchmark score was measured.
