# llama.cpp `cb999704`: IQ4_XS Vulkan dequantization

**Verdict: `EQUIV_PARTIAL`.** The historical parent and child `DATA_A_IQ4_XS` `dequantize4` functions differ only in how they read four quantized bytes. The parent reads `qs[iq+0..3]` individually; the child reads packed32 `qs[iq/4]` and calls `unpack8`. The unchanged scale, lookup, and multiplication expressions therefore receive identical four nibble values on the covered path.

[`reproduce.py`](reproduce.py) reads both exact Git blobs, checks that the selected functions differ only by this load rewrite, and checks the historical `types.glsl` layout and `copy_from_quant.comp` caller. That caller uses `j = 0,4,...,252` with `QUANT_R_IQ4_XS = 1`. [`proof.smt2`](proof.smt2) proves that its `iq` is four-aligned and that, for every 32-bit packed word and both nibble shifts, no output lane differs. Z3 returns `unsat` for both queries in [`proof.log`](proof.log). Run `python3 -B history-eq/gpu/llama.cpp/cb999704/reproduce.py` from the project root.

The relation assumes that packed32 `qs` is the same four-byte storage as the scalar `qs` view and that `unpack8` maps the least-significant byte to the first lane, as specified by [GL_EXT_shader_explicit_arithmetic_types](https://docs.vulkan.org/glslext/latest/glslext/ext/GL_EXT_shader_explicit_arithmetic_types.html). It covers this dequantization function with four-aligned indices, including `copy_from_quant`; the other changed GLSL paths, compiled SPIR-V, and whole Vulkan execution are unproved. Z3 was invoked directly; **Kuiper did not verify this historical pair**. No official before/after benchmark score was measured.
