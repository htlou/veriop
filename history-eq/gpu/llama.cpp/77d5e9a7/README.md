# `77d5e9a7`: row conversions moved to CPU backend

**Scoped verdict: `EQUIV_PARTIAL`.** The historical `get_rows_bf16` caller changes from `ggml_bf16_to_fp32_row` to `ggml_cpu_bf16_to_fp32`, while the public core row function becomes scalar. [`reproduce.py`](reproduce.py) checks the exact old/new `ggml.c`, `ops.cpp`, and conversion-header blobs plus the new `ggml-cpu.c` blob, extracts the historical functions, and supplies eight arbitrary BF16 words by value. It compares all eight FP32 output **bit patterns**, including NaN encodings, for `n=8` with AVX2 enabled and AVX512F disabled.

The [new core row](forward.log) and [old core row](backward.log) have distinct Clang 20 `-O1` LLVM bodies. Alive2 proves both directions for every output position: 16/16 checks pass. The caller's actual [new CPU backend](backend-forward.log) and [old row](backend-backward.log) also pass 16/16 bidirectional checks; their eight specialized LLVM bodies are identical after compilation. Only TBAA and loop-hint metadata were removed symmetrically from the compared IR.

The commit also redirects FP32→FP16 conversion from the old core row function to `ggml_cpu_fp32_to_fp16`. With eight arbitrary FP32 input bit patterns, `n=8`, and F16C/AVX2 enabled, the old row and new backend pass [8/8 forward](fp16-backend-forward.log) and [8/8 backward](fp16-backend-backward.log) Alive2 checks. Their specialized LLVM function bodies are identical. A separate comparison of the old and retained new *core* row functions is [inconclusive](fp16-core-diagnostic.log): Alive2 cannot model `llvm.x86.vcvtps2ph.128`; it produces no counterexample.

The [result](result.json) records source blobs, IR hashes, and all checker summaries. Other lengths, other CPU feature settings, the FP32→FP16 new-core path, and whole-commit behavior remain unproved. No official historical before/after benchmark score was measured. Reproduce from the project root with `python3 -B history-eq/gpu/llama.cpp/77d5e9a7/reproduce.py`.
