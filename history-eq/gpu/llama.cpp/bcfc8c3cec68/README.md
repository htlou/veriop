# llama.cpp `bcfc8c3cec68` — Hexagon activation scratchpad boundary

**Verdict: `NOT_EQUIV` for the destination write footprint of the selected FP32 SiLU path.** Both historical revisions of `execute_op_activations_fp32` accept a scratchpad reservation holding **one row per thread**. The child then halves each per-thread buffer for ping-pong DMA, computes `BLOCK = (src0_spad.size_per_thread / 2) / aligned_row_size`, and returns from its worker when `BLOCK == 0`. The parent has no such return: for an aligned nonempty row it calls `hvx_mul_f32_opt` with the destination pointer. The historical implementation of that helper has explicit destination stores. The outer dispatcher keeps its success return even when the child worker exits early.

A concrete accepted resource configuration uses the historical 128-byte HVX width, the 8 MiB default VTCM reservation, four threads, four rows, and 512 KiB per FP32 row: `floor(8 MiB / (4 × 3 × 512 KiB)) = 1` row per thread. The parent reaches the output writer; the child computes `BLOCK = (512 KiB / 2) / 512 KiB = 0` and leaves the destination untouched. [Alive2](alive2-gate.log) finds the corresponding source-locked write-marker mismatch at one row per thread (`1` before, `0` after). A [native harness](native_harness.c) compiles the **exact old and new `unary_silu_fp32_per_thread` function bodies** with scalar stand-ins for Hexagon helpers. Its [old](old.log) and [new](new.log) logs show one output-writer call versus zero and a changed sentinel destination versus an unchanged one.

Run `python3 -B history-eq/gpu/llama.cpp/bcfc8c3cec68/reproduce.py` from the project root. It checks exact Git blob hashes, the unchanged outer acceptance gate, the child early return, and the historical HVX destination-store code before building the harness and [Alive2 projection](old-gate.c). [result.json](result.json) records the revisions and witness.

This establishes the selected write-footprint/control-flow difference. The scalar stand-ins do **not** establish a specific numerical result on Hexagon hardware; actual device execution, other activation variants, and whole-commit behavior remain untested. No official before/after benchmark score was measured. Kuiper was not used.
