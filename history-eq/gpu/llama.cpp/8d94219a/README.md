This case corrects an earlier overclaim. An initial source-extracted Alive2 model compared the old F32 byte-copy branch with the new F32 `from_float` callback on one 4×3×2×1-to-2×12 reshape. With a 4-byte source-alignment assumption, Alive2 proved both directions; without it, old→new was refuted because the new callback's `float*` input induced an alignment requirement. Those logs remain here as a diagnostic. **Neither result describes a reachable F32→F32 execution of the historical duplicate dispatcher.** `audit_reachability.py` checks the exact old/new `ops.cpp` blobs: both have one call to `ggml_compute_forward_dup_f32`, and both dispatchers first route every same-type pair through `ggml_compute_forward_dup_bytes` and return. Thus the modeled F32→F32 branch cannot be reached through that caller, regardless of reshape. The checker outcomes must not be counted as optimization equivalence or inequality evidence.

The reachable F32→other-type path still deserves a separate check if this commit is studied for another reason; the two-loop bodies appear unchanged apart from a callback variable name. The new `SET_ROWS` operation has no old implementation to compare under this historical commit. This record establishes neither whole-commit equivalence nor an official before/after benchmark delta.
