# llama.cpp `010be9683afa` — Intel OpenCL Q4_K/Q5_K tile tuning

**Verdict: `EQUIV_PARTIAL` for the selected matrix-multiply tile mapping when the Intel host and shader conditions agree.** The historical Q4_K and Q5_K kernel bodies from `kernel void` onward are byte-identical; the change selects `TM=8, TN=8` under `cl_intel_required_subgroup_size` in place of `TM=4, TN=8`. The host changes the matching Intel workgroup size from 128 to 64. For both layouts, exhaustive mapping of all work items, microtile rows, and columns covers the same 4,096 cells of a 64×64 output tile exactly once and fills the same 2,048 positions of each 32×64 local input tile exactly once. [Z3 independently excludes two work items writing the same output cell](old-unique.smt2) for [both layouts](intel-unique.smt2). Both historical Q4_K/Q5_K kernels pass Clang OpenCL syntax checking with and without the Intel extension macro; compiler diagnostics are archived beside the checker inputs.

The extension macro is a necessary precondition for the new Intel layout. If the host selects Intel's 64-thread launch but the kernel is compiled without `cl_intel_required_subgroup_size`, it retains the 4×8 microtile and only 2,048 of 4,096 full-tile output cells have writers. This is a source-level configuration mismatch control, **not a measured Intel device failure**.
