# llama.cpp `03ea0417`: WebGPU `set_rows` vector-load counterexample

**Verdict: scoped `NOT_EQUIV`.** The historical change selects a `vec4<f32>` shader whenever `src->ne[0]` is divisible by four. The host passes the source's binding misalignment in **scalar elements**, but the vector shader indexes `src[i_src_row/4 + col_idx]`. If a four-element F32 source is a contiguous view starting four bytes into a five-element allocation, `offset_src=1` with a 256-byte storage-buffer alignment. For its first element, the old scalar shader reads `src[1]`; the new vector shader reads lane zero of `src[0]`, i.e. `src[0]`. Setting those values to `1.0` and `0.0` respectively makes the first F16 output `0x3c00` before and `0x0000` after.
