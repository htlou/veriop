# llama.cpp `cc9e331213b6` — SYCL MoE routed-row layout

**Verdict: `EQUIV_PARTIAL` for a bounded routing and scatter relation.** The historical parent assigns each routed row a per-expert slot through an atomic counter; the child sorts all rows by expert on the host, copies them in one launch, then scatters the results through the row map. For two slots per token, two tokens, and three possible experts, Z3 proves that both layouts give every route a distinct slot in its expert's interval for every valid router assignment and every permutation of the four old atomic assignments. If each matrix row computes the same value for the same expert and source row, the two layouts scatter identical abstract row values back to each original `(slot, token)` position. Z3 also produces a witness that the internal contiguous-row order can differ, so the proof does not claim bytewise identity of intermediate buffers.

Run `python3 -B history-eq/gpu/llama.cpp/cc9e331213b6/reproduce.py` from the project root. It checks both exact Git blob IDs for `ggml-sycl.cpp`, source-locks the old atomic mapping, new prefix-sum and row-map construction, and unchanged source/destination indexing. It compiles the **exact new counting-sort function extracted from the historical C++ source** into [a small native harness](native_harness.cpp), which passes all 81 router assignments of this shape ([log](native.log)). [Z3 inputs and outputs](layout.smt2) cover slot range/uniqueness (`unsat`), [abstract scatter equality](scatter.smt2) (`unsat`), and an [internal-order witness](internal-order.log) (`sat`). The [result record](result.json) contains the revision and source hashes.

The SMT relation abstracts each matrix result as a per-route value. It does not prove the actual SYCL matrix kernels, GPU stream ordering, arbitrary tensor dimensions, floating-point results, or the whole commit. The installed Kuiper package supplied the Z3 executable; **Kuiper itself did not verify this historical pair**. No official before/after benchmark score was measured.
