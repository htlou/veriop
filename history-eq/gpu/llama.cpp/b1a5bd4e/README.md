# llama.cpp `b1a5bd4e`: contiguous concat layout

The historical commit replaces three contiguous CUDA concat kernels with one template that distributes elements linearly across CTAs. The only changed source file is `ggml/src/ggml-cuda/concat.cu`; the exact parent, child, and Git blob IDs are locked in [the reproduction script](reproduce.py). This optimization was found in the nonkeyword history audit and is **outside the current 200-commit llama.cpp sample**.

Run `python3 -B history-eq/gpu/llama.cpp/b1a5bd4e/reproduce.py` from the project root. It archives both exact historical `ggml/` trees, compiles [old](old.ptx) and [new](new.ptx) CUDA to SM80 PTX, and uses Volta to compare `concat_f32_dim0` with `concat_f32_cont<0>`. The kernels have different parameter signatures, so [old-normalized.ptx](old-normalized.ptx) reorders the old `ne00`/`ne0` parameter declarations and adds four unused declarations to match the new logical argument order. The script asserts that the old PTX **instruction body is byte-identical** before and after this ABI adaptation; all tested dimensions fit the old 32-bit parameters. [The result record](result.json) retains compile and checker commands, outputs, source/PTX hashes, and blob IDs.

**Verdict: `EQUIV_PARTIAL`.** Volta returned `EQUIVALENT` for all output elements in six one-CTA dim-0 shapes: output lengths 2, 7, 32, 129, 255, and 256, each with nonempty `x` and `y` segments. The one-CTA grid is the complete output for each shape. Volta's comparison executes CTA 0, so this does not prove the multi-CTA layouts, dim-1/dim-2 kernels, or the whole commit. Kuiper was not used. No official historical llama.cpp benchmark score was measured for this pair.
