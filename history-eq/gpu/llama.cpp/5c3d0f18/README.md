# llama.cpp 5c3d0f18: AVX Q4_0/Q8_0 dot product changes floating results

**Fixed-sample verdict: `NOT_EQUIV` for the existing `ggml_vec_dot_q4_0_q8_0` AVX path.** The [exact historical production diff](../source-screening/5c3d0f18.source.diff) changes its per-block AVX accumulation from one accumulator to two alternating accumulators. The function still handles an odd final block in its unchanged scalar tail. With four valid Q4_0/Q8_0 blocks, the [same native witness](Witness.c) returns `32` in the parent and `64` in the child. This is a strict floating-point result difference caused by reassociation: a large positive block and a large negative block cancel, while the two small positive blocks are rounded differently between the two accumulation orders.

Run `python3 history-eq/gpu/llama.cpp/5c3d0f18/reproduce.py` from the project root. It archives the complete `ggml/` tree at each historical revision, verifies the target source against Git, compiles both full original `ggml-quants.c` translation units with Clang 20 for AVX and without AVX2/FMA, links the identical witness, and asserts the two outputs. The harness initializes only its two accessed FP16 lookup-table entries with the same historical `GGML_COMPUTE_FP16_TO_FP32` macro used by `ggml.c`, then checks that `0x3c00` and `0x7bff` decode to `1` and `65504`. [The result record](verification-result.json) stores source and LLVM IR hashes, build flags, and observations. No official llama.cpp performance score was measured for this historical pair.

Alive2 on the complete old/new function [does not finish in the recorded time limit](full-alive.log); that run is **not** a full-function Alive2 counterexample. A separate, [source-mapped single-lane recurrence](Reduction.old.c) / [optimized recurrence](Reduction.new.c) uses the witness's concrete lane contributions. [Alive2 reports one incorrect transformation](ReductionFixed.alive.log), returning `4` before and `8` after for one lane. The `NOT_EQUIV` classification rests on the exact historical full-function native execution, with the local Alive2 result identifying its arithmetic cause.
