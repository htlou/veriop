# llama.cpp `76614f35`: cached AArch64 SVE vector length

The [exact historical diff](../source-screening/76614f35.source.diff) replaces `svcntb() == QK8_0` and `svcntw() == 8` guards with `ggml_sve_cnt_b == QK8_0`. The new global is set once at `ggml_init` from `prctl(PR_SVE_GET_VL)`. [Source audit](audit_source.py) checks those expressions, the historical `QK8_0 == 32`, and that a failed `GGML_ASSERT` reaches `abort()`.

[Alive2's bidirectional result](alive2/result.json) compares the source-derived guard and assertion-outcome projections. With both vector lengths constrained to valid 16-byte multiples, unrestricted old/new Q8 and GEMV guards are **not equivalent**. For the assertion in `ggml_gemv_q4_0_4x4_q8_0`, [Alive2 gives](alive2/fwd.log) current VL **16 bytes**, cached VL **32 bytes**, and SVE available: the old guard skips the abort, while the new guard enters it. The archived source places that guard after only the dimension assertions, so a dimension-valid call can reach it. Linux [documents](https://docs.kernel.org/arch/arm64/sve.html) that `PR_SVE_SET_VL` changes only the calling thread's VL, leaving other threads unaffected; a successful change after `ggml_init` can therefore create this state on hardware supporting both lengths. Arm's [ACLE](https://arm-software.github.io/acle/main/acle.html) defines `svcntb` as a byte count and `svcntw` as a word count.

When the current VL equals the cached VL, the three corresponding [Alive2 stable-VL projections](alive2/result.json) are **bidirectionally equivalent**. **Fixed-sample verdict: `NOT_EQUIV` for the selected assertion outcome under a post-init VL change.** This is an exact-source branch projection, not a compile-and-compare proof of the complete AArch64 matrix multiplication or quantized dot-product functions. There is no local AArch64 SVE hardware execution or official before/after performance score for this historical pair.
