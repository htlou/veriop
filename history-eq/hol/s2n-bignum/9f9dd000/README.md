# s2n-bignum `9f9dd000`: historical x86 multiplication rewrite

**Verdict: `REFINES` at the x86-64 subroutine ABI boundary under the shared HOL Light preconditions.** Parent `cba7bcb9557dd0238674b603a97a4941ca130c95`; child `9f9dd0002c9ef5ab1db2ddb7d1fdaa26824c3b3b`. The commit changes only `x86/fastmul/bignum_mul_8_16.S` and its HOL Light proof script. Its message says the ADCX-to-ADC changes reduce code size and may slightly improve performance. No official before/after benchmark score was measured.

The two historical revisions are in [`old`](../../../wt/s2n-mul8-old/x86/proofs/bignum_mul_8_16.ml) and [`new`](../../../wt/s2n-mul8-new/x86/proofs/bignum_mul_8_16.ml). Each script states `BIGNUM_MUL_8_16_CORRECT` and `BIGNUM_MUL_8_16_SUBROUTINE_CORRECT`, with the same 8-limb-by-8-limb functional output (`a * b`) but different code-length preconditions. Their `define_assert_from_elf` lines refer to the revision's own assembled object. The assembled object SHA-256 values differ: old `8063076d61e902acc20325f1ada6b54d8c2397dfc17351d19bfc26ce2ba626ba`, new `286f2c05ec002dffd735ef4152d8511ae8d62c3ff79517c355ee44cb4b93f18d`.

The first [old](../../../wt/s2n-mul8-old/x86/fastmul/bignum_mul_8_16.correct) and [new](../../../wt/s2n-mul8-new/x86/fastmul/bignum_mul_8_16.correct) runs failed while loading historical common libraries. Their Makefile exit code 0 was not proof evidence. The [OCaml 5.3 port script](port_hol_5_3.py) now copies both exact revisions to temporary worktrees and changes only 32 host-language `Int` numeral constructions per side to `Num.num_of_int`; it also loads compiler-libs, Zarith, and the installed HOL Light modules, and exposes `Printf.bprintf` under its historical name. The target assembly and proof scripts remain byte-identical to their historical revisions. The [port manifest](port-manifest.json) records the changed files and counts.

Both reruns completed with process exit 0, no `Error:` or `Exception:`, and generated `BIGNUM_MUL_8_16_CORRECT` and `BIGNUM_MUL_8_16_SUBROUTINE_CORRECT` as HOL Light theorems. The full [parent log](ported-old-proof.log.gz), [child log](ported-new-proof.log.gz), extracted [parent theorems](ported-old-theorems.txt), [child theorems](ported-new-theorems.txt), and [audit](ported-proof-summary.json) are archived. [`check_ported_proofs.py`](check_ported_proofs.py) rechecks the log content and object hashes. The printed main theorem statements differ only in machine-code length (`1272` versus `1227` bytes) and the corresponding RIP exit offset (`1261` versus `1216`); the subroutine theorem statements differ only in code length. Both guarantee `bignum_from_memory (z,16) = a * b`, and the subroutine theorems preserve the return address and stack pointer as specified.

The two `SUBROUTINE_CORRECT` theorems have identical postconditions and `MAYCHANGE` sets after replacing their code lengths. Starting from related states with the same arguments, eight-limb inputs, return address, and stack pointer, and satisfying both code/data nonoverlap preconditions, each subroutine returns to that address with the same stack pointer and the exact 16-limb product `a * b`. All locations outside the common `MAYCHANGE` set are preserved. This gives the child the same ABI-observable result and frame guarantee as the parent on that shared domain. Caller-saved scratch registers, flags, timing, and other platforms are outside this observation.
