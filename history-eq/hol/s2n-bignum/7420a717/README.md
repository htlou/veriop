# s2n-bignum `7420a717`: x86 multiplication and squaring changes

**Verdict: `EQUIV_PARTIAL` for all nine changed arithmetic subroutines.** This commit changes nine x86 multiplication/squaring/reduction routines and their HOL Light proofs ([historical diff](../source-screening/7420a717.source.diff)). Both exact historical assembly objects and proof scripts were replayed for every changed routine. The results establish common output specifications under shared preconditions; they do not establish unrestricted whole-commit equivalence.

[Preparation](prepare.py) binds the complete diff and the selected parent/child assembly and proof scripts to their exact Git objects, ports four unchanged support files for the installed OCaml 5.3, and assembles both historical objects. The [source audit](source-audit.json) records the object hashes and the newer support revision. Both HOL Light replays finished and generated `BIGNUM_MUL_4_8_CORRECT` and `BIGNUM_MUL_4_8_SUBROUTINE_CORRECT`: [parent log](old-proof.log), [child log](new-proof.log). [The proof audit](check_proofs.py) checks the source/object hashes, absence of errors, each theorem's output clause, and equality of the theorem statements after normalizing only the code size and RIP exit offset. Its [result](proof-result.json) and [extracted statements](old-theorems.txt) ([child](new-theorems.txt)) are archived.

The same preparation and audit scripts with `bignum_mul_6_12` also replayed both exact historical objects and generated `BIGNUM_MUL_6_12_CORRECT` and `BIGNUM_MUL_6_12_SUBROUTINE_CORRECT`: [source audit](source-audit-mul6.json), [parent log](old-mul6-proof.log), [child log](new-mul6-proof.log), [proof result](proof-result-mul6.json), and extracted [parent](old-mul6-theorems.txt) and [child](new-mul6-theorems.txt) statements. The subroutine statements agree after normalizing their code sizes and RIP exit offsets; both guarantee `bignum_from_memory (z,12) = a * b` with the same return and change footprint under shared preconditions.

The 8-by-8-limb pair likewise passed both historical HOL Light replays: [source audit](source-audit-mul8.json), [parent log](old-mul8-proof.log), [child log](new-mul8-proof.log), [proof result](proof-result-mul8.json), and extracted [parent](old-mul8-theorems.txt) and [child](new-mul8-theorems.txt) statements. Both subroutine theorems guarantee `bignum_from_memory (z,16) = a * b` with matching return and change footprint under shared preconditions.

The three squaring pairs also passed the same exact-source and two-sided theorem audit: [4-limb result](proof-result-sqr4.json), [6-limb result](proof-result-sqr6.json), and [8-limb result](proof-result-sqr8.json). Each pair's `CORRECT` and `SUBROUTINE_CORRECT` statements agree after normalizing only the historical code length and RIP exit offset. Their outputs are respectively 8, 12, and 16 limbs containing `a EXP 2`; each source audit, replay log, and extracted theorem is archived under the matching `sqr4`, `sqr6`, or `sqr8` suffix.

The [Montgomery-reduction result](proof-result-emontredc.json) audits both exact historical `bignum_emontredc_8n` objects and proof scripts ([parent](old-emontredc-proof.log), [child](new-emontredc-proof.log)). Its subroutine theorems have identical statements after accounting for code length. Both prove the same arithmetic equation relating the output memory and carry to the input **when** `8` divides the limb count and `(n * w + 1) ≡ 0 (mod 2^64)`. The separate [HOL Light uniqueness theorem](emontredc-output-uniqueness-theorem.txt), proved by [this script](emontredc-output-uniqueness.ml) and checked against the paired proofs by [this audit](check_output_uniqueness.py), shows that the equation uniquely determines the low-limb output, high-limb output, and return value given the same input and standard `BIGNUM_FROM_MEMORY_BOUND` limb bounds ([result](emontredc-output-uniqueness-result.json)). Thus those three outputs agree for old and new executions under the shared preconditions and the Montgomery antecedent. Outside that antecedent, and for other mutable state, equivalence is not established.

The [16-limb Karatsuba-squaring result](proof-result-ksqr16.json) audits both exact historical `bignum_ksqr_16_32` objects and proof scripts ([parent](old-ksqr16-proof.log), [child](new-ksqr16-proof.log)). Both `CORRECT` and `SUBROUTINE_CORRECT` statements agree after normalizing the parent's 3560-byte code/`pc+3549` exit and the child's 3460-byte code/`pc+3449` exit. The shared subroutine theorem guarantees the 32-limb output equals `a EXP 2` under its nonoverlap preconditions.

The [32-limb Karatsuba-squaring result](proof-result-ksqr32.json) audits both exact historical `bignum_ksqr_32_64` objects and proof scripts ([parent](old-ksqr32-proof.log), [child](new-ksqr32-proof.log)). Both generated `SUBROUTINE_CORRECT` statements agree after normalizing the parent's 5804-byte and child's 5702-byte code regions. The shared theorem guarantees the 64-limb output equals `a EXP 2`, returns to the same address, and has the same listed change footprint under its nonoverlap preconditions. This script has no separate `CORRECT` theorem.

For `mul_4_8`, the parent's code is 344 bytes and exits its main body at `pc+341`; the child's is 340 bytes and exits at `pc+337`. For `mul_6_12`, those values are 740/`pc+733` and 734/`pc+727`; for `mul_8_16`, 1280/`pc+1269` and 1272/`pc+1261`. In the eight multiplication/squaring pairs, both subroutine theorems guarantee the same arithmetic output, return address, stack pointer, and listed change footprint under their respective nonoverlap preconditions. Therefore those output relations hold under the intersection of their preconditions. The Montgomery pair adds conditional equality of its low/high outputs and return value, as above. This is not a whole-commit proof, byte-for-byte state equivalence, or a timing result. No official before/after benchmark score was measured.

Finally run `python3 -B history-eq/hol/s2n-bignum/7420a717/check_proofs.py` once without an argument and once with each named target. The support tree is newer than the 2021 commit; the target assembly and proof scripts are exact historical files.

For the Montgomery uniqueness result, run `emontredc-output-uniqueness.ml` through the same HOL Light/OCaml setup from `benchmarks/tools/hol-light`, save its output as `emontredc-output-uniqueness.log`, and run `python3 -B history-eq/hol/s2n-bignum/7420a717/check_output_uniqueness.py` from the project root.
