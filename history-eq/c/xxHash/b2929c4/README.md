# xxHash `b2929c4`: AVX-512 scramble XOR fusion

Run `python3 -B history-eq/c/xxHash/b2929c4/check_ternary.py` from the project root. The [result](ternary-proof.json) checks the complete archived old/new `xxhash.h` Git blobs and confirms that this commit changes exactly one expression in that header. The old expression computes `acc_vec ^ shifted ^ key_vec`; the new one uses `_mm512_ternarylogic_epi32(key_vec, acc_vec, shifted, 0x96)`.

Intel defines this intrinsic's `imm8` as a per-bit lookup table on the three inputs ([Intel compiler reference](https://www.intel.com/content/www/us/en/docs/cpp-compiler/developer-guide-reference/2021-8/intrinsics-int-bit-manip-and-conflict-detect-ops.html); see also the [Intel AVX-512 guide](https://cdrdv2-public.intel.com/633930/IntelAVX-512_InstructionSetForPacketProcessing_TechGuide_633930v3.pdf)). The exhaustive eight-row table shows that `0x96` selects precisely the odd-parity rows, so the replacement is equal for every bit of every 512-bit input vector. A changed immediate, `0x95`, fails the negative control. Since all following instructions and all other source code are identical, the AVX-512 scramble's output and every defined caller's functional outputs are equal for arbitrary valid input buffers. This is a source-level compositional proof, not an Alive2 verdict for the raw AVX-512 intrinsic.

The earlier [five public API checks](r_api_avx512.out) pass bidirectional Alive2 on fixed-size inputs, while the [arbitrary-buffer raw Alive2 check](r_raw_avx512.out) remains `UNKNOWN`. Those results remain recorded separately. This source proof does not establish identical timing, machine code, or behavior for executions with undefined C behavior; it does not supply an official xxHash before/after benchmark score.
