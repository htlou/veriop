# xxHash `7bf3d9f`: XXH64 tail finalizer

**Verdict: `EQUIV_PARTIAL`.** The commit changes only `xxhash.h`; the exact old and new header Git objects are checked by [the proof audit](check_finalizer.py). The changed function `XXH64_finalize` replaces a switch-based tail with loops. Its old switch path dispatches on `len & 31`; the old rerolled path and the new function both first apply `len &= 31`. Thus, for the same initial hash value, pointer, and alignment mode, testing each of the 32 residues covers every `size_t` length passed to this finalizer.

[The common wrapper](wrap_finalizer.c) invokes the historical function directly with symbolic input pointer and initial 64-bit hash. It instantiates every residue `0..31` for both `XXH_aligned` and `XXH_unaligned`. The existing [Alive2 runner](../_tools/alive_check_f.py) compiled that wrapper against the historical parent and child headers with Clang 20 on x86-64 and checked both refinement directions. It did this for the old switch configuration (`XXH_REROLL=0`, [results](finalizer-raw/result.json)) and the old rerolled configuration (`XXH_REROLL=1`, [results](finalizer-reroll/result.json)). All **128 function pairs** returned `EQUIV`; the normalized IR contains no loops, and no Alive2 loop-unroll bound was used. [The audit result](finalizer-proof-audit.json) checks source object IDs, IR/log hashes, all 128 outcomes, and the absence of errors or timeouts.

This proves the raw finalizer's returned value on the defined input domain for the tested x86-64/default-memory-access compilation and both alignment modes. It does not prove complete public one-shot or streaming APIs, other architectures, or other memory-access compile configurations. Earlier fixed-length public API checks remain in the commit's existing artifacts; some streaming cases were inconclusive. No official historical before/after benchmark score was measured.
