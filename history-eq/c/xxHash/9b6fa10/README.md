# xxHash `9b6fa10`: scalar stripe accumulator

The exact archived parent and child `xxh3.h` files have Git blob IDs `a66489ba6401632bf03bbf773740f7f56da8f7b7` and `9b662ae7ebdb112aa3627dc8ee5e7bb90ad4c256`. The changed scalar loop processes adjacent lanes in a different order. The same commit also changes an ARM inlining condition, so the scalar result is not a whole-commit proof.

For x86-64 Clang 20 with `XXH_VECTOR=0`, Alive2 proves both directions for the complete 64-byte accumulator output at **both** `XXH3_acc_64bits` and `XXH3_acc_128bits`. The wrappers copy arbitrary initial accumulator bytes into a fresh aligned array before calling the exact historical helper, then copy all eight output lanes back. The [64-bit](pre_acc512_64_scalar/result.json) and [128-bit](pre_acc512_128_scalar/result.json) records include the old/new IR hashes and forward/reverse logs. Re-running the bidirectional checks returns one correct transformation and no failed transformations for each mode.

An additional [source-locked algebra check](check_scalar_algebra.py) uses the exact header Git blob IDs and models the old pair-at-a-time and new lane-at-a-time updates in their original order. For arbitrary eight 64-bit initial accumulator lanes, data words, and product words, Z3 reports [`unsat`](scalar-64.log) for a 64-bit-mode output difference and [`unsat`](scalar-128.log) for a 128-bit-mode difference. A deliberately wrong 128-bit lane selection reports [`sat`](scalar-negative.log). The shared product word abstracts the identical per-lane source expression and assumes input and secret are disjoint from the modified accumulator. This removes the x86-specific arithmetic concern, but it is a direct Z3 model, not a Kuiper or whole-C-program proof.

An earlier [raw-pointer attempt](raw_acc512_scalar/result.json) timed out. Its label says the accumulator might alias the input or secret; that possibility is outside the C99 `XXH_RESTRICT` contract when the accumulator is modified, and actual library callers use a separate accumulator. The local-copy proof covers this disjoint-accumulator scalar specialization without relying on `restrict` as a compiler assumption. It does not cover the ARM inlining change, other vector configurations, or all public hash lengths. The selected commit therefore remains `EQUIV_BOUNDED`, counted as unverified for the full historical comparison.

From the project root, check the archived source IDs with `git hash-object history-eq/c/xxHash/9b6fa10/{old,new}/xxh3.h` against `git -C benchmarks/repos/xxHash rev-parse '9b6fa10^:xxh3.h'` and `git -C benchmarks/repos/xxHash rev-parse '9b6fa10:xxh3.h'`. The exact Alive2 commands are stored in the two result JSON files.
