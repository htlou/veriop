# xxHash `11126e3`: pointer-object alignment declarations

The complete historical commit changes only `xxhash.h`. [`audit_defined_outputs.py`](audit_defined_outputs.py) checks the archived parent and child against their Git blob IDs, then removes the nine `XXH_ALIGN(...)` prefixes on local `xacc` pointer declarations from the parent. The resulting header is **byte-identical** to the child. In this header, `XXH_ALIGN` expands to a storage-alignment specifier (or nothing), and no `xacc` object's address is taken. The pointer values, pointee alignment assertions, expressions, function bodies, and call sites are otherwise unchanged.

The same audit compiles the exact headers with Clang 20 `-O3` and checks `target_acc512` and `target_scramble` in both Alive2 directions for scalar, SSE2, AVX2, and AVX512 selection. All **16/16** checks pass; the normalized LLVM modules also pass `opt -passes=verify`. The [machine-readable result](defined-outputs-audit.json) points to each check log. Run `python3 -B history-eq/c/xxHash/11126e3/audit_defined_outputs.py` from the project root to reproduce it.

**Selected verdict: scoped `EQUIV` for functional outputs and memory effects on defined C executions.** Removing a storage-alignment specifier from an unobserved local pointer object does not change its value or any access through it. The complete source audit covers all nine changed declarations, including the NEON branch; Alive2 independently checks the four x86 implementations listed above. It does not prove identical machine code, timing, stack layout, compilation diagnostics, or resource use on every compiler. No official historical benchmark delta was measured.
