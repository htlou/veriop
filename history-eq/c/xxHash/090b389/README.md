[`revalidate_a64.py`](revalidate_a64.py) verifies the parent and child Git blob IDs, compiles both historical headers with the same complete 64-byte stripe wrapper, and reruns Alive2 in both directions for both 64-bit and 128-bit accumulation modes. The fresh LLVM IR hashes match the archived checks; the target bodies differ, contain no unresolved calls or inline assembly, and have no loops. Both [forward](a64-recheck-fwd.log) and [reverse](a64-recheck-bwd.log) logs report two correct transformations and zero errors or failed proofs. The [result](a64-recheck-result.json) records source, model, IR, and log hashes.

**Verdict: scoped `EQUIV`.** For the AArch64 NEON build, the complete 64-byte accumulator output agrees for arbitrary initialized accumulator, input, and secret bytes in both accumulation modes. The shared [`neon_model.h`](neon_model.h) replaces NEON unsigned widening multiplication with the corresponding zero-extended lane arithmetic on both sides because Alive2 does not interpret that intrinsic directly. This is a semantic-model assumption, explicitly recorded in the result. The separate archived ARMv7 checks also passed under the same model, but the current recheck and selected full-scope label rely on AArch64 only.

Public hash APIs, other targets and compilers, and execution time are outside this proof. No official historical benchmark score is claimed. Reproduce from the project root with `python3 -B history-eq/c/xxHash/090b389/revalidate_a64.py`.
