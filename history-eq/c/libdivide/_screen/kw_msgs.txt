=================== 78fc01d
78fc01d 2021-03-06
Allow using all vector types simultaneously
Prior to this change, libdivide supported at most one vector type (SSE2, AVX2,
AVX512), selected at configure time. With this change all vector types may be
supported simultaneously.
A nice advantage here is easier testing. Now all vector widths may be tested
simultaneously instead of requiring separate build directories for each one.
Also migrate the benchmark tool from C to C++. This was written in C because at
the time clang did not support C++ (!) and I was curious about performance
under clang. Now that C++ is supported by clang, we can use its niceties.
This requires an API change. Instead of 'do_vector' we now tag it with the
vector width. So the new functions are:
	libdivide_s32_do_vec128
	libdivide_s64_do_vec128
	libdivide_u32_do_vec128
	libdivide_u64_do_vec128
	libdivide_s32_do_vec256
	libdivide_s64_do_vec256
	libdivide_u32_do_vec256
	libdivide_u64_do_vec256

=================== 8e9bf17
8e9bf17 2021-03-06
Reimplement vectorized high-multiplies
The previous implementations were taken from StackOverflow, but the
licensing there is ambiguous. Revert back to the previous implementation
which was bespoke and so covered by the libdivide license, and use it in
all vector regimes.
One new idea relative to the old implementation is to use a shuffle
instead of a shift when moving the high 32 bits of packed 64 bit values
into lower lanes. The advantage of a shuffle is that it preserves the
source register which saves us a mov.
